# 软件设计大赛 · 项目大纲（骨架）

> 用法：把每个「写」下面换成你自己的内容，然后删掉所有提示行。
> 这份骨架是给**校赛**（10 分钟展示 + 现场演示 + 答辩，评委是本院老师 + 企业校友）写的。
> 校赛不评商业模式，所以没有"财务分析""市场空间"这些章节——写了反而占地方。

---

## 0. 一句话

> 格式：给**谁**，在**什么场景**下，用**什么**，解决**什么**，靠**什么**跟别人不一样。

**写：**

**别写：** 「一款基于 AI 的创新型编程学习平台」——这句话可以套在任何项目上，等于什么都没说。

---

## 1. 问题

> 评委在第 1 分钟就在判断：这是真问题，还是他们想出来的问题。

**写：** 一个人、一个时刻、一个具体到能演出来的动作。
（例：晚上十一点，大一新生写完作业跑起来，终端报 `IndentationError`，他盯着屏幕不知道该搜什么。）

**别写：** 行业趋势、市场规模、"随着人工智能的发展……"

**自检：** 这段能不能让评委想起自己班上的某个学生？想不起来就是还没写对。

---

## 2. 方案

> 一条主流程，不超过 5 步。评委记不住 12 个功能，但记得住 5 步。

**写：**

1.
2.
3.
4.
5.

**必须明确写出：哪里是人做的，哪里是机器做的。**
（这一行是分水岭：没写，评委会认为你在"包装 AI"；写了，都知道你懂自己在干什么。）

## 提交前自检清单

- [ ] 全文没有「我们计划」「将来会」这类没有主语的抱负
- [ ] 每个数字都有出处（自己数出来的也算，但要说明怎么数的）
- [ ] 每个"创新点"都能指出它在哪个文件的第几行 / 哪个页面
- [ ] 10 分钟能讲完，且**前 40 秒**就有一个具体场景
- [ ] 断网了还能演示（或至少能讲清楚会看到什么）
- [ ] 现场演示的那个人，练过至少 3 遍，包括翻车的走位
- [ ] 每一节都能回答「所以呢？」——答不出来的句子直接删

## 附：不同比赛的同类文件叫什么

同一套骨架，换个名字出现在不同赛事里：

| 赛事 | 文件名称 | 侧重 |
|---|---|---|
| 中国国际大学生创新大赛（原"互联网+"） | 项目计划书 | 商业闭环：执行概述 / 产品与服务 / 市场分析 / 运营成果 / 公司管理 / 战略规划 / 财务分析 / 风险管理；评审看教育、创新、团队、商业、社会价值五个维度 |
| "挑战杯" | 作品申报书 + 研究报告 | 学术性、成果的可验证性 |
| 中国大学生计算机设计大赛 | 设计说明书 + 安装使用说明 + 演示视频 | 作品完整度与可复现性 |
| 校赛 / 院赛（你们这个） | 大纲 / PPT / 作品简介 | **能不能跑、是不是你做的、讲不讲得清** |

校赛只需要最后一行那三件事。所以这份骨架故意没有商业章节——
评委是你的任课老师和毕业的学长，他们只会问：这东西真能用吗？这是你写的吗？
