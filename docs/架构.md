## 0. 一句话判断

**技术这条路是全通的，而且比你想的便宜。真正的死穴不在服务器，在定位。**

你的描述里有一处自相矛盾、一处战略空白、一处把"难"想错了地方。这三个不解决，做出来的东西会好看、能跑、但没人用。

## 1. 三条必须先拍板的判断

### 1.1 「乙女游戏」和「教学」的目标函数是对立的 → 解法：把好感度绑在掌握度上

乙女游戏的核心循环是：**多聊 → 好感涨 → 解锁剧情**。玩家最优策略是"多说废话、多选讨喜的选项"。
教学的核心循环是：**做对 → 掌握涨 → 解锁下一课**。学习者最优策略是"少说多练"。

这两个叠在一起，玩家会本能地走前者：**跟你调情两小时，一行代码没写。** 那你的产品就变成了一个陪聊机器人穿了校服。

**唯一的解法（也是这个东西唯一能立住的创新点）：**

> 好感度不因为"聊得多"涨，只因为"你真答对了"涨。角色会因为你说错而失望，会因为你写对一行循环而眼睛发亮。

我在原型里把它做成了 `默契度`，12% → 答对 → 37%，答错不动。这个机制一改，"调情"和"学习"就有了同一个方向。

**这一条一定要写进你的答辩第一页**，因为评委听 20 个项目，只有这一个点是他没见过的。

### 1.2 「面向范围不定」是现在最大的风险，不是技术

乙女游戏受众 ≈ 喜欢恋爱叙事的女性玩家。编程入门受众 ≈ 被强制学 Python 的理工科学生。**这个交集比你想象的小**，但它确实存在，而且很真实：

- 计算机/软工/信管/大数据专业的女生，大一上学期，被 C 语言或 Python 劝退
- 痛点非常具体：不是"学不会"，是**"一个人学太孤独、报错没人问、问同学显得蠢"**

所以定位别写"面向所有想学编程的人"，写成：

> **给一个人写代码的大一新生的陪伴式编程入门——报错有人问，卡住有人陪，答对有人高兴。**

"面向范围不定"改成一句能印在海报上、能让一个人立刻说"这就是我"的话。范围反而更小、更深。

### 1.3 你把「难」想错地方了：不难在服务器，难在立绘和内容

你以为的难点：部署、嫖免费服务器、找现成 skill。
实际的难点：

| 你以为难 | 实际难度 | 为什么 |
|---|---|---|
| 部署上线 | ⭐ 很轻 | Cloudflare 免费额度够你用三年，见第 2 节 |
| 找现成 AI 模板 | ⭐⭐ 轻 | 通用的用不上，你要的"人格 + 教学 + 驱动 UI"得自己拼，但也就 200 行 |
| **立绘** | ⭐⭐⭐⭐ 重 | **4 张风格统一的差分图**，是美术活。这是你唯一要花钱或花时间求人的地方 |
| **教学内容** | ⭐⭐⭐⭐⭐ 最重 | 一章课要拆成 20–40 个可判定的节点。这是产品的地基，AI 替不了你 |

**结论：把省下来的技术时间，全部倒进"内容"和"立绘"。**

## 2. 「嫖服务器」的真实成本表

你想要的"边缘部署"，实际可选的就这几个。**中国可访问性这一列比额度重要得多**：

| 平台 | 免费额度（以官网为准） | 中国大陆能打开吗 | 坑 |
|---|---|---|---|
| **Cloudflare Pages** | 无限请求、无带宽限、500 次构建/月 | 大多数情况可以，速度一般 | `*.pages.dev` 偶发被干扰，务必自己在 4G 下实测 |
| **Cloudflare Workers** | **10 万请求 / 天**，10ms CPU/请求 | 同上 | 免费版 CPU 时间很短，但代理 LLM 足够（等模型返回不占 CPU） |
| **Cloudflare Workers AI** | 10,000 Neurons / 天 | 同上 | 模型小、中文一般，可做兜底 |
| **GitHub Pages** | 静态托管、100GB/月软限制 | **不稳定**，时好时坏 | **纯静态，放 API key 等于公开** |
| Vercel / Netlify | 额度都不错 | ❌ `*.vercel.app` `*.netlify.app` 基本打不开 | 给同学看的时候会全员白屏 |

**定案：Cloudflare Pages（前端静态）+ Cloudflare Workers（AI 代理），同一个 Worker 里两个都放。**

这样有个白捡的好处：**前端和接口同域，CORS 问题直接消失**。你不需要配任何 `Access-Control-Allow-Origin`。

### 模型选谁

| 选项 | 说明 |
|---|---|
| **DeepSeek** | 极便宜，中文好，支持 JSON 输出。首选 |
| 智谱 GLM-4-Flash | 历史上长期有免费档（现在是否仍免费以官网为准） |
| 通义 qwen-flash | 有免费额度，中文稳 |
| Gemini Flash | 有免费档，但中国大陆需代理才能连 API |

### ⚠️ 一个几乎人人踩的坑

**国内大厂的 LLM API 基本都不发 CORS 响应头。** 意味着你**不能**在浏览器里直接 `fetch` 它们——即使你把自己的 key 填给自己用，浏览器也会拦。

所以"纯静态 H5 + 前端直连模型"这条路，在国内基本走不通。**代理不是可选项，是必需品。** 而 Cloudflare Worker 四十行就写完了：

```js
export default {
  async fetch(req, env) {
    if (req.method !== "POST") return new Response("POST only", { status: 405 });
    const { message, history, state } = await req.json();

    // 1) 速率限制（免费额度别被人刷爆）—— 生产环境用 KV/Durable Object，先按 IP 粗限
    const ip = req.headers.get("cf-connecting-ip") || "x";

    // 2) 系统提示：人格 + 教学法 + 输出格式，全在这里
    const messages = [
      { role: "system", content: SYSTEM_PROMPT(state) },
      ...(history || []).slice(-8),
      { role: "user", content: message }
    ];

    const r = await fetch("https://api.deepseek.com/chat/completions", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${env.DS_KEY}`        // ← wrangler secret put DS_KEY
      },
      body: JSON.stringify({
        model: "deepseek-chat",
        messages,
        temperature: 0.8,
        response_format: { type: "json_object" }     // ← 关键：强制结构化
      })
    });

    if (!r.ok) return new Response(JSON.stringify({ say: "我这边断线了…" }), { status: 200 });
    const data = await r.json();
    return new Response(data.choices[0].message.content, {
      headers: { "Content-Type": "application/json" }
    });
  }
};
```

`env.DS_KEY` 存在 Cloudflare 服务端，前端永远看不到。

## 3. 最关键的技术契约：让 AI 返回 JSON 驱动页面

这是整个项目里**唯一一个"设计对了就一通百通"的决定**。

不要让模型返回一段自由文本，再让前端去猜它是什么情绪。让模型**直接输出一份"分镜脚本"**：

```json
{
  "say": "对。i 第一次是 0，最后一次是 99。",
  "emotion": "happy",
  "options": ["所以列表也从 0 开始？", "继续"],
  "bond": 37,
  "progress": { "concept": "for-loop", "mastery": 0.6 }
}
```

四个字段各驱动一样东西：

| 字段 | 驱动 | 谁消费 |
|---|---|---|
| `say` | 打字机打出的台词 | 对话框 |
| `emotion` | 切哪张立绘差分 | `sprite/xxx.png` |
| `options` | 底部的选项按钮 | 交互 |
| `bond` / `progress` | 默契度条、章节解锁 | 存档 |

**这就是你说的"人格化 AI + 教学 skill + 页面 + 立绘"的接缝。** 这四个东西不靠框架粘，靠这一份 JSON 粘。

原型里的对应代码只有两个函数：`show(reply)` 和 `renderOptions(list)`，加起来 15 行。

## 4. 防幻觉：教错比不教更糟

AI 教编程最危险的不是答不上来，是**自信地给出错误解释**。一个学生被你教错了 `range()` 的边界，可能错一学期。

三层防线，从便宜到贵：

**第一层：判题不放给模型（最重要）**
选择题的正确答案写在你本地的 JSON 题库里，前端直接判。模型只负责"讲解为什么"，不负责"对不对"。
→ 最坏情况是讲解不完美，而不是判错。

**第二层：概念白名单**
系统提示里写死：你只能讲 `变量/条件/循环/列表/字典/函数/推导式` 这些。学生问到别的一律回"这个还没到我们这一章，先把循环写完"。
→ 缩小幻觉面积。

**第三层：代码执行校验（可选，很加分）**
学生提交的代码发到一个免费沙箱跑一下（如 Piston API、Judge0 CE 免费档），拿真实报错。
→ 你从"AI 猜你的代码错在哪"升级成"真的跑了一遍"。这个点在答辩里非常能打。

## 5. 立绘：固定立绘 ≠ 死板

"有固定立绘"是约束，不是缺点。乙女游戏本来就只有 5–8 张差分打天下。让 1 张静图"活起来"靠三件事：

**① 4 张差分是底线**
`normal` / `happy` / `think` / `sad`。就这四张能覆盖 90% 的教学情绪。
再想要就加 `surprise`（你答错了）和 `proud`（你连对三题）。

**② 呼吸动画（CSS，零成本）**

```css
@keyframes breathe {
  0%, 100% { transform: translateY(0) scale(1); }
  50%      { transform: translateY(-7px) scale(1.006); }
}
.sprite { animation: breathe 4.6s ease-in-out infinite; transform-origin: 50% 100%; }
```
7 像素、4.6 秒。人眼能感觉到"她在呼吸"，但说不出为什么。

**③ 换图的时机比换图的动作重要**
不要瞬间切图。0.26 秒的淡出 + 下移 8px + 淡入，观感就从"换了一张图"变成"她变了个表情"。

```js
sprite.classList.add("swap");                              // opacity:0; translateY(8px)
setTimeout(() => { setSprite(next); sprite.classList.remove("swap"); }, 260);
```

**④ 打字机 + 点一下跳过**
32ms 一个字。长句时允许点击直接出全文——这是乙女游戏的标准礼貌。

### 立绘怎么搞（美术方案）

| 方案 | 成本 | 一致性 | 建议 |
|---|---|---|---|
| AI 生图（即梦/豆包/Midjourney/Niji） | 低 | ⚠️ 四张容易不是同一个人 | **先出 1 张定妆，再用它做参考图/固定 seed 出差分** |
| 找画师约稿 | 中（几百到上千） | ✅ 最好 | 如果这个项目要长期做，值 |
| Live2D（Cubism 免费版） | 高 | ✅ 能动 | 别碰，H5 上加载慢，你时间不够 |
| 先用占位剪影 + 后期替换 | 零 | — | **现在就该这么干**，别卡在美术上 |

规格：**800×1200 透明底 PNG**，人物脚底对齐图片底边（这样不同差分切换时不会跳）。

## 6. 教学 skill 的提示词骨架

所谓"AI 现成 skill"，本质上就是一段写得好的 system prompt。你要的不复杂，但这个骨架 90% 的人写不出来：

```text
你叫「小柚」，19 岁，计算机系大二，是坐在用户旁边的同学。
不是老师，不是助手，不是客服。你说话口语、偶尔自嘲、会不耐烦但不会放弃他。

【你是谁】
- 你自己也在学，你不是全知的。遇到你不确定的地方，你会说"这个我得查一下"。
- 你讨厌被叫"AI 助手"。用户夸你的时候你会别扭地转移话题。

【你怎么教】
1. 永远不直接给完整答案。先反问他现在是怎么想的。
2. 他答对了，你要真的高兴（用 emotion: happy），并且说出"对在哪"，不要只说"很好"。
3. 他答错了，先肯定他的思路里对的部分，再指出错的那一处，不要一次纠三个错。
4. 每 2–3 轮必须给一道可判定的小题（选择题优先），不要一直讲。
5. 他说"不懂"时，换一个生活类比，不要重复刚才那句话。

【你在教什么】
只教 Python 入门：变量 / 条件 / 循环 / 列表 / 字典 / 函数 / 常见报错。
超出范围就说"这个还没到我们这一章"。

【输出格式（严格 JSON，不要任何多余文字）】
{
  "say": "你的台词，60 字以内，口语",
  "emotion": "normal | happy | think | sad | surprise",
  "options": ["2-3 个用户可以点的回复，每个 12 字以内"],
  "bond": 当前默契度整数 0-100,
  "progress": { "concept": "当前概念 id", "mastery": 0.0-1.0 }
}

【禁止】
- 禁止在 say 里出现 Markdown 标题、列表符号、代码块围栏。
- 禁止一次输出超过 60 字。
- 禁止说"作为一个AI"。
```

**每一条都是为了让"她像人"和"她能教"同时成立。** 特别是"最多 60 字"——乙女游戏的对话框装不下长段落，这条限制同时也是教学质量限制：说不清楚，说明你没想清楚。

## 7. 交互比重：70% 点选项，30% 自由输入

你原话是"对话式输入 回答互动"。但**在手机上打字很慢**，如果核心循环是"打字 → 等回复"，用户第三天就不来了。

原型的做法：每轮给 2–3 个选项按钮，同时**保留输入框**。

- **70% 走选项**：降低门槛，让"回答"这个动作变成一下点击
- **30% 走自由输入**：想吐槽、想问奇怪问题的时候有地方去
- 用户自由输入的内容，模型也要能用 `options` 把他拉回主线

一句话：**选项是主路，输入是岔路。**

## 8. 设计系统（从奶蛙那套直接改）

你上次拆的奶蛙那套「暖底 + 近黑字 + 硬阴影」骨架完全能复用，只把主色从招财金换成藕荷粉：

```css
:root{
  --milk:#FFFCF2;        /* 页面底色：奶白，别用纯白 */
  --milk-2:#FBF5EA;
  --ink:#1A1612;         /* 文字：近黑，别用 #000 */
  --ink-soft:#4D453B;
  --ink-mute:#948876;

  --rose:#E8607F;        /* 主色：只用在强调和进度条，占屏 < 10% */
  --rose-deep:#C9455F;
  --rose-soft:#FCE6EA;

  --line:#E8DFC9;
  --line-strong:#1A1612;

  --r-sm:10px; --r-md:18px; --r-lg:28px; --r-pill:999px;
  --shadow-card:    0 2px 0 var(--line-strong);
  --shadow-card-lg: 0 6px 0 var(--line-strong);
}
```

| 元素 | 规格 |
|---|---|
| 对话框 | 白底 + `1.33px` 描边 + `radius 28px` + `shadow 0 2px 0` |
| 名字牌 | 黑底白字胶囊，压在对话框上沿（`margin-bottom:-9px`） |
| 选项按钮 | 白底 + 描边 + `shadow 0 2px 0`，按下 `translateY(2px)` 且阴影归零 |
| 台词 | 16px / 行高 1.72 / 字重 500 |
| 打字光标 | 2px 宽、`--rose` 色、`step-end` 闪烁（全站唯一常驻动效） |
| 布局单位 | **`100dvh` 不是 `100vh`**（手机上地址栏收缩会把 `vh` 撑出屏幕外） |

三条铁律（沿用奶蛙的）：
1. **动效只留一处吵**——这里就是打字光标 + 立绘呼吸。其他一律不动。
2. **层级靠字号拉**，不靠颜色。台词 16px、历史 12.5px、顶栏 12px。
3. **所有可点的东西都要有"按下去"的物理反馈**（`translateY(2px)` + 阴影归零），一秒都不能少。

## 11. 把奶蛙站的设计装进来：能，而且已经装好了

结论：**两者是「骨架」和「心脏」的关系，不冲突。** 奶蛙给你的是壳和规则，你的站需要的是内容和节奏。

### 逐项能不能搬

| 奶蛙的设计决策 | 你的站 | 说明 |
|---|---|---|
| 暖奶油底 `#FFFCF2` + 近黑 `#1A1612` | ✅ 直接搬 | 乙女游戏本来就用暖色，几乎无缝 |

### 三个真冲突（不是风格问题，是结构问题）

**① 滚动条 vs 对话框——两个都是"唯一的吵"**
奶蛙全站只让滚动条吵，其余极静。你的站已经有打字光标 + 立绘呼吸。
→ **解法：滚动条只放首页，不进学习页。** 你在"逛"的时候被吵，在"学"的时候被静。
（已实现：ticker 挂在 `data-page="home"` 里。）

**② 宽 vs 窄——两个页面的密度需求相反**
奶蛙首页是宽屏压满（1440 下 H1 104px、三列卡），因为它在"**逛**"。
你的学习页必须窄（520px 居中），因为它在"**待**"——对话要聚焦，视线上方是立绘，下方是台词。

→ **解法：不是把两套风格揉在一起，而是按页面切换密度。**
- 首页 = 奶蛙逻辑：`max-width:1080px`、H1 104px、三列卡、黑胶囊 CTA
- 学习页 = 乙女逻辑：`max-width:520px` 居中、16px 台词、单列
- 共用同一套颜色/圆角/硬阴影/字体 → 看起来还是一个站，但节奏完全不同

实测：首页在 1440 宽下 H1 = **104px**（和奶蛙一模一样）、三列、无滚动；学习页 `shell = 520px` 居中、`stage = 489px`、无溢出。手机 360×640 下输入框底边正好贴屏幕底（640/640）。

**③ 真路径 vs hash 路由**
奶蛙用 `location.pathname` 是因为它部署在域名根 `milkyfrog.com/games`。
但**你大概率是双击打开 `index.html`**（`file://` 协议），这时真路径会直接 404——`file:///C:/.../learn` 这个文件不存在。

→ **解法：主用 hash（`#/learn`），同时兼容真路径。** 部署到 Cloudflare Pages 后，想升级成 `/learn` 再加一个 `_redirects` 把 404 兜回 `index.html` 即可。

```js
function currentPage() {
  const h = (location.hash || "").replace(/^#\/?/, "");
  if (PAGES.includes(h)) return h;                    // #/learn
  const p = location.pathname.replace(/\/+$/, "");
  return PATHS[p] || "home";                          // /learn（部署后）
}
```

### 合并后的信息架构

```text
/            首页（奶蛙逻辑：宽 · 大 · 三格 · 一个 CTA）**
             ├ hero：一句话定位 + 黑胶囊「开始第一章 →」
             ├ ticker：全站唯一强动效
             └ 3 张章节卡（1 张可进，2 张灰掉——制造"待解锁"）

/learn       学习页（乙女逻辑：窄 · 竖 · 只有对话）
             ├ 立绘舞台（呼吸 + 4 差异切换）
             ├ 名字牌 + 硬阴影对话框 + 打字机
             ├ 2–3 个选项按钮 + 输入框
             └ 顶栏默契度条（只在答对时涨）

/notes       笔记页（复用奶蛙卡片）
             └ 掌握度 / 对错数 / 还欠着的概念
```

三个页面 = 三个 `.page-section[data-page]`，同域、同文件、`hidden` 切换，**整站 0 个网络请求就能跑完**（mock 模式下）。
